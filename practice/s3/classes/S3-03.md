# S3-03 — HTMX: interactividad sin frontend separado

## Contexto

Las vistas de `S3-02` funcionan, pero cada acción recarga la página entera — cancelar un turno hace parpadear toda la agenda para actualizar una sola fila. Esto es exactamente el problema que justificó elegir Django + HTMX en vez de una API separada con frontend en JavaScript: acá se resuelve sin escribir una línea de JS propio ni mantener un frontend aparte.

## Concepto mínimo

**La idea central de HTMX.** El servidor sigue devolviendo HTML, no JSON. HTMX intercepta la petición, la manda por AJAX en vez de navegación completa, y reemplaza solo el fragmento indicado del DOM con el HTML que devuelve el servidor.

**Los atributos que importan:**
- `hx-post="/turnos/1/cancelar"` — qué petición hacer y a dónde.
- `hx-target="#turno-1"` — qué elemento del DOM se reemplaza.
- `hx-swap="outerHTML"` — cómo se reemplaza (el elemento completo, no solo su contenido interno).
- `hx-confirm="¿Cancelar este turno?"` — confirmación antes de disparar la petición.

```html
<div id="turno-1">
  <button hx-post="/turnos/1/cancelar" hx-target="#turno-1" hx-swap="outerHTML" hx-confirm="¿Cancelar este turno?">
    Cancelar
  </button>
</div>
```

**La vista de Django no cambia de naturaleza.** Sigue siendo una función que devuelve HTML — la diferencia es que ahora devuelve un fragmento pequeño (la fila actualizada del turno) en vez de la página completa, cuando la petición viene de HTMX.

## Demostración

El mentor toma la vista de "cancelar turno" de `S3-02` y la convierte: el botón usa `hx-post`, la vista detecta la petición y devuelve solo el fragmento de esa fila actualizado, mostrando en el navegador cómo la fila cambia sin que la página parpadee.

## Laboratorio

Con guía: agregar `hx-get` con `hx-trigger="keyup changed delay:300ms"` a un campo de búsqueda de pacientes, filtrando la lista en vivo sin recargar.

## Ejercicio

Sin guía: convertir el formulario de "crear turno" de `S3-02` para que se envíe por HTMX, mostrando errores de validación inline sin recargar la página completa.

## Challenge

Investigá `hx-indicator` para mostrar un estado de carga mientras la petición está en curso, y `hx-swap-oob` (out-of-band swap) para actualizar, en una sola respuesta, tanto la fila del turno como un contador de turnos del día en otra parte de la página.

## Project Task

1. Aplicar HTMX a "cancelar turno" y "crear turno" como mínimo.
2. Confirmar que ninguna de las dos requiere JavaScript propio para funcionar.
3. Commit: `Agregar interactividad con HTMX a las vistas core`.

## Evidencia — Definition of Done

- [ ] Al menos dos interacciones reales usan HTMX en vez de recarga completa de página.
- [ ] No se escribió JavaScript propio para lograrlo.
- [ ] Podés explicar qué significa "swap" y dónde se define el elemento objetivo, con tu propio ejemplo.

## Bibliografía de esta clase

## Nota sobre abstracción

HTMX es una implementación puntual de una idea más general (hipermedia como motor del estado de la aplicación — HATEOAS). El concepto de actualizar fragmentos de HTML server-rendered sin un framework de frontend completo existe en otras herramientas similares (Turbo/Hotwire en el ecosistema Rails, por ejemplo) con sintaxis distinta pero la misma filosofía.
