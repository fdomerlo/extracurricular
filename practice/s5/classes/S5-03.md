# S5-03 — Métricas, observación y diagnóstico de incidentes

## Contexto

Esta clase junta tres cosas que hasta ahora existían por separado: los logs estructurados de `S4-03`, el criterio de `EXPLAIN` de `S2-03`, y la pregunta que define si un sistema está realmente en producción o solo desplegado: ¿te enterás de que algo falló antes de que te lo digan?

## Concepto mínimo

**Un `health check` mínimo.** Un endpoint (`/health/`) que confirma que la aplicación responde y que puede hablar con la base de datos — no "el servidor está prendido", sino "el sistema puede hacer su trabajo".

```python
def health_check(request):
    try:
        Turno.objects.exists()
        return JsonResponse({"status": "ok"})
    except Exception:
        return JsonResponse({"status": "error"}, status=503)
```

**Un monitor externo, no manual.** Un servicio gratuito (hay varios) que pega a `/health/` cada pocos minutos y avisa si deja de responder — esto es lo que responde al criterio de `custom-plan.md`: "un tablero o registro mínimo de estado del sistema, accesible sin entrar al servidor" y "te enterás de que el sistema se cayó antes de que te llamen".

**Performance, revisitando `S2-03` con datos reales.** Con el sistema en uso real, alguna consulta que era rápida con datos de prueba puede volverse lenta con volumen real. El mismo `EXPLAIN ANALYZE` de `S2-03` es la herramienta — ahora aplicada bajo condiciones reales, no hipotéticas.

**Diagnóstico de incidente, con evidencia, no con intuición.** Cuando algo falla, la secuencia es: mirar el `health check` (¿qué falla, la app o la base?), mirar los logs estructurados de `S4-03` filtrados por el momento del incidente, y recién ahí formular una hipótesis — el mismo proceso de `S1-08`, aplicado a infraestructura en vez de a código.

## Demostración

El mentor configura el endpoint de salud y un monitor externo gratuito apuntando a él, mostrando el dashboard resultante. Después simula un incidente real (por ejemplo, detiene el servicio de PostgreSQL) y diagnostica en vivo: el monitor externo avisa, el `health check` devuelve error, los logs muestran la excepción de conexión — reconstruyendo la causa con evidencia, no adivinando.

## Laboratorio

Con guía: correr `EXPLAIN ANALYZE` sobre una consulta real del proyecto con volumen de datos representativo, buscando alguna que se haya vuelto notablemente más lenta desde `S2-03`.

## Ejercicio

Sin guía: si se encontró una consulta lenta en el laboratorio, resolverla (índice, reescritura) y confirmar la mejora con `EXPLAIN ANALYZE` antes/después — mismo método de `S2-03`, ahora sobre un caso real, no de ejemplo.

## Challenge — el ejercicio integrador del semestre

El mentor simula un incidente **sin decir cuál es**, en algún punto del sistema (podría ser el mismo tipo del `S1-08`/`S1-09` pero ahora a nivel de infraestructura: base caída, disco lleno, servicio de `systemd` detenido). El estudiante lo diagnostica solo, usando el `health check`, el monitor externo y los logs — sin acceso directo a lo que el mentor cambió, solo con la evidencia que el propio sistema genera.

## Project Task

1. `/health/` funcional y monitor externo configurado.
2. Al menos una consulta lenta real encontrada y resuelta con evidencia de `EXPLAIN ANALYZE`.
3. `INCIDENT_LOG.md` documentando el diagnóstico del Challenge: qué pasó, cómo se detectó, cómo se confirmó la causa, cómo se resolvió.

## Evidencia — Definition of Done

- [ ] Hay un tablero o registro de estado accesible sin entrar al servidor.
- [ ] Te enteraste de una caída simulada por el monitor, no porque alguien te avisó primero.
- [ ] Diagnosticaste el incidente del Challenge con evidencia (logs, health check), documentado en `INCIDENT_LOG.md` — no adivinando la causa.
- [ ] Encontraste y resolviste al menos una consulta lenta real, con evidencia de `EXPLAIN ANALYZE`.

## Nota sobre abstracción

Health checks, monitoreo externo y diagnóstico basado en evidencia son prácticas universales de operación de sistemas, independientes de stack. La herramienta de monitoreo concreta cambia; el método de diagnóstico —evidencia antes que intuición— no.
