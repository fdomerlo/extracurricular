# S6-01 — Observabilidad

## Contexto

Tenés logs estructurados (`S4-03`) y métricas básicas (`S5-03`) por separado. Lo que falta es la capacidad de reconstruir, paso a paso, qué pasó durante una operación específica de principio a fin — no solo que algo falló, sino exactamente dónde en el camino.

## Concepto mínimo

**Los tres pilares de la observabilidad:** logs (eventos discretos), métricas (números agregados en el tiempo), y trazas (el recorrido completo de una operación específica, con tiempos por etapa). Ya tenés los dos primeros — esta clase agrega el tercero, de forma liviana.

**Trazas sin herramienta pesada.** No hace falta adoptar un sistema de tracing distribuido completo (OpenTelemetry, por ejemplo) para un sistema de esta escala — alcanza con timestampear cada etapa importante de una operación, usando el mismo identificador de correlación de `S4-03`, y después reconstruir la línea de tiempo filtrando por ese identificador.

```python
logger.info("turno_creacion_inicio", extra={"correlation_id": cid})
# ... validación ...
logger.info("turno_creacion_validado", extra={"correlation_id": cid, "duracion_ms": ...})
# ... guardado en base ...
logger.info("turno_creacion_guardado", extra={"correlation_id": cid, "duracion_ms": ...})
```

## Demostración

El mentor instrumenta el flujo de creación de turno con timestamps en cada etapa, genera una operación real, y reconstruye la línea de tiempo completa filtrando los logs por el `correlation_id` — mostrando cuánto tardó cada paso, no solo la operación completa.

## Laboratorio

Con guía: instrumentar de la misma forma el flujo de cancelación de turno.

## Ejercicio

Sin guía: usando la línea de tiempo reconstruida, identificar cuál etapa de un flujo elegido es la que más tiempo consume realmente — confirmando o corrigiendo una suposición previa.

## Challenge

Investigá OpenTelemetry como la versión "completa" de lo que esta clase hizo de forma liviana, y documentá con qué señal concreta (mismo criterio de `S4-06`) se justificaría adoptarlo en vez de este enfoque manual.

## Project Task

1. Instrumentación de tiempos en los 2-3 flujos más importantes del proyecto.
2. `OBSERVABILITY.md` resumiendo qué se registra y cómo consultarlo.

## Evidencia — Definition of Done

- [ ] Podés responder "¿está caído? ¿está lento? ¿desde cuándo? ¿por qué?" usando solo las herramientas propias del proyecto — sin adivinar.
- [ ] Reconstruiste la línea de tiempo completa de al menos un flujo real, con tiempos por etapa.
- [ ] `OBSERVABILITY.md` documenta qué se registra y cómo se consulta.
