# S6-06 — Portfolio y comunicación técnica del proyecto

## Contexto

Tres años de decisiones, errores y correcciones no se explican solos. Esta clase construye la narrativa del proyecto — lo que le vas a mostrar a alguien técnico en una entrevista, y lo que le contarías a tu papá o a un amigo sin ningún trasfondo de programación.

## Concepto mínimo

**Dos versiones, dos audiencias.** Cinco minutos para alguien técnico: el problema real, dos o tres decisiones de arquitectura con su trade-off, un error real que cometiste y cómo lo corregiste. Dos minutos para alguien no técnico: qué hace el sistema, para quién, y por qué importa — sin jerga.

**La historia real, no la lista de funcionalidades.** Un buen portfolio técnico no es "implementé X, Y, Z". Es "el problema era este, elegí este camino por esta razón, en el medio esto salió mal, así lo corregí, y esto es lo que aprendí" — el mismo criterio que ya pedía `custom-plan.md` desde el principio: problema → decisiones → errores → refactors → tests → despliegues → incidentes.

**Un error real cuenta más que un éxito genérico.** Contar honestamente algo que salió mal y cómo se corrigió demuestra más criterio profesional que una lista de features que funcionaron a la primera.

## Demostración

El mentor ayuda a armar en vivo el borrador del pitch técnico de 5 minutos, insistiendo en que tenga un problema concreto, una decisión con trade-off real (por ejemplo, Django+HTMX en vez de API separada, de `custom-plan.md`), y un error real (por ejemplo, algo encontrado en `S6-03` o `S4-04`).

## Laboratorio

Con guía: armar la versión de 2 minutos para audiencia no técnica, traduciendo la jerga.

## Ejercicio

Sin guía: escribir `PORTFOLIO.md` (o reestructurar el `README.md` del proyecto) contando la evolución real completa, no solo el estado final.

## Challenge

Practicá el pitch de 5 minutos con alguien que no sea el mentor —un amigo, un familiar con algo de trasfondo técnico— y traé feedback real, no solo tu propia sensación de cómo salió.

## Project Task

`PORTFOLIO.md` completo, los dos pitches (técnico y no técnico) ensayados y con feedback externo incorporado — esto alimenta directamente la defensa de `S6-08`.

## Evidencia — Definition of Done

- [ ] Podés dar el pitch técnico en 5 minutos y el no técnico en 2, dentro del tiempo.
- [ ] `PORTFOLIO.md` incluye al menos un error real y cómo se corrigió, no solo logros.
- [ ] Conseguiste feedback de alguien que no sea el mentor.
