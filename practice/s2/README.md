# S2 — Persistir y servir

## Theme

**Build reliable applications**

## Focus

Persistencia, SQL, motor relacional, APIs, arquitectura de aplicaciones y seguridad básica. HTTP como protocolo no vive acá: se ve en `S3-01`, antes del framework web.

## Estructura

- 15 clases principales.
- Mentoría aproximadamente cada 2 semanas.
- Trabajo autónomo entre clases.
- Proyecto longitudinal.
- Milestone al finalizar.

## Proyecto

Transformar el dominio de S1 en una aplicación persistente con un motor relacional y una API HTTP segura y testeada.

## Regla pedagógica

La clase introduce una capacidad. El proyecto obliga a usarla en contexto. La mentoría revisa decisiones. El milestone evalúa integración.

## Clases

- **01** — SQL y modelado relacional
- **02** — Motor relacional en desarrollo
- **03** — Persistencia y repositorios
- **04** — Transacciones y consistencia
- **05** — Diseñar APIs
- **06** — Validación y contratos
- **07** — Autenticación y autorización
- **08** — Seguridad de aplicaciones
- **09** — Arquitectura de servicios
- **10** — Errores, logging y configuración
- **11** — Testing de integración
- **12** — Performance básica
- **13** — Entornos locales reproducibles
- **14** — Integración de aplicación
- **15** — Milestone: aplicación funcional

## Milestone

**M-S2 — Aplicación persistente y API**

La calidad se evalúa por evidencia y capacidad de explicación, no por cantidad de código ni por cantidad de tecnologías utilizadas.
