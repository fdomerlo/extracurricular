# S2-07 — Interfaz de acceso operativo: Django Admin como backoffice

## Contexto

El objetivo del Semestre 2 no es desarrollar aún una aplicación web pública con vistas personalizadas (eso corresponde a **S3**, donde aprenderás HTTP, HTML, CSS, JavaScript y HTMX). El objetivo de S2 es **dotar al sistema de persistencia y de una interfaz de acceso controlada** que permita a los operadores del consultorio (la secretaria, los odontólogos, los administradores) gestionar los datos reales con seguridad y sin depender de scripts de terminal.

El panel de administración de Django (`django.contrib.admin`), lejos de ser un mero prototipo de desarrollo, es un backoffice de grado de producción cuando se configura profesionalmente. En esta clase aprenderás a transformar un registro genérico de modelos en una herramienta operativa intuitiva, eficiente y protegida contra errores de carga humana.

---

## Concepto mínimo

**1. Registrar modelos frente a Configurar `ModelAdmin`.**  
El comando `admin.site.register(TurnoModel)` proporciona una grilla genérica que muestra cadenas de texto simples. Un `ModelAdmin` configurado a medida define:
- `list_display`: Qué columnas exactas se muestran en la tabla (ej. horario formateado, paciente con DNI, profesional, práctica y badges de estado).
- `list_filter`: Paneles laterales de filtrado rápido (por fecha, especialidad, sobreturnos o cancelaciones).
- `search_fields`: Búsqueda de texto completo (ej. buscar turnos por DNI o apellido del paciente mediante sintaxis de relación `paciente__dni`, `paciente__apellido`).
- `date_hierarchy`: Navegación cronológica nativa por año, mes y día (`date_hierarchy = "fecha"`).

**2. Optimización del Admin (Evitar N+1 en la interfaz).**  
El panel de administración sufre el problema N+1 al listar filas que muestran claves foráneas. La directiva `list_select_related` es obligatoria en cualquier `ModelAdmin` con relaciones:
```python
list_select_related = ("paciente", "profesional", "practica")
```
Esto reduce las consultas de una página de 100 turnos de 301 consultas a solo 1 consulta SQL unificada.

**3. Acciones de Administración personalizadas (`Admin Actions`).**  
Permiten a los operadores realizar cambios masivos sobre los elementos seleccionados con checkboxes (por ejemplo: *"Marcar como confirmados los turnos seleccionados"* o *"Generar comprobante de asistencia"*), ejecutando transacciones atómicas.

**4. Campos de solo lectura (`readonly_fields`).**  
Los identificadores `UUID` y las marcas temporales de auditoría (`creado_en`) no deben ser editables manualmente por los usuarios en el formulario web.

## Ejemplo trabajado conceptual

Configuración de una vista de administración profesional para un modelo de facturas:

```python
from django.contrib import admin
from .models import FacturaModel

@admin.register(FacturaModel)
class FacturaAdmin(admin.ModelAdmin):
    list_display = ("numero", "cliente_nombre", "monto_formateado", "estado", "fecha_emision")
    list_filter = ("estado", "fecha_emision")
    search_fields = ("numero", "cliente__nombre", "cliente__cuit")
    date_hierarchy = "fecha_emision"
    readonly_fields = ("id", "creado_en")
    list_select_related = ("cliente",)

    @admin.display(description="Monto Total")
    def monto_formateado(self, obj):
        return f"${obj.monto:,.2f}"

    @admin.action(description="Marcar facturas seleccionadas como Pagadas")
    def marcar_pagadas(self, request, queryset):
        filas_actualizadas = queryset.update(estado="PAGADA")
        self.message_user(request, f"{filas_actualizadas} facturas actualizadas con éxito.")

    actions = [marcar_pagadas]
```

## Ejercicio

Configurá en `agenda/admin.py` la clase `TurnoAdmin` para gestionar la agenda del consultorio:

1. **Grilla de Turnos:**
   - Columnas a mostrar: `fecha`, `hora_inicio`, `hora_fin`, paciente (nombre y DNI), profesional, práctica médica, y si es sobreturno.
   - Filtros laterales: por fecha (`list_filter = ["fecha", "profesional", "es_sobreturno"]`).
   - Búsqueda: por apellido o DNI del paciente (`search_fields = ["paciente__apellido", "paciente__dni"]`).
   - Optimización estricta: `list_select_related = ["paciente", "profesional", "practica"]`.
2. **Formulario de Carga:**
   - Los campos `id` y `creado_en` deben ser `readonly_fields`.
   - Utilizá `autocomplete_fields = ["paciente", "profesional"]` para que la selección de pacientes en una base grande no cargue miles de opciones en un `<select>` plano (requiere configurar `search_fields` en `PacienteAdmin`).
3. **Acción Masiva:**
   - Creá una acción `marcar_como_sobreturno` que actualice los turnos seleccionados seteando `es_sobreturno = True`.
