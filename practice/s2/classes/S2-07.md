# S2-07 — Django admin como interfaz de acceso

## Contexto

Todavía no hay vistas propias — eso es `S3`. Pero el consultorio no tiene por qué esperar hasta entonces para empezar a usar el sistema: el admin de Django, bien configurado, es una interfaz real de trabajo, no un panel de desarrollador. Es el primer punto donde tu papá o la secretaria pueden tocar el sistema con las manos.

## Concepto mínimo

**Registrar un modelo es el mínimo; configurarlo es lo que lo hace usable.** `admin.site.register(Turno)` te da una tabla genérica. Un `ModelAdmin` bien pensado es la diferencia entre "funciona" y "alguien sin conocimientos técnicos lo puede usar sin ayuda".

```python
from django.contrib import admin
from .models import Paciente, Profesional, Turno

@admin.register(Paciente)
class PacienteAdmin(admin.ModelAdmin):
    list_display = ("nombre", "apellido", "dni", "telefono")
    search_fields = ("dni", "nombre", "apellido")

@admin.register(Turno)
class TurnoAdmin(admin.ModelAdmin):
    list_display = ("fecha", "hora_inicio", "paciente", "profesional", "practica")
    list_filter = ("profesional", "fecha")
    ordering = ("fecha", "hora_inicio")
```

**`list_display`** define qué columnas se ven en la lista — pensado desde lo que la secretaria necesita ver de un vistazo, no desde los campos que existen en el modelo. **`search_fields`** habilita la búsqueda (por DNI, por nombre) — sin esto, encontrar un paciente entre miles es prácticamente inusable. **`list_filter`** agrega filtros laterales (por profesional, por fecha).

**`TabularInline`** muestra registros relacionados dentro de la página de otro modelo — por ejemplo, ver los turnos de un profesional directamente en su página de edición, sin navegar a otra sección.

## Demostración

El mentor configura `PacienteAdmin` con `search_fields` en vivo, y hace la prueba real: buscar un paciente por DNI parcial, confirmando que aparece en menos de lo que tardaría scrolleando una lista sin filtrar.

## Laboratorio

Con guía: agregar `list_filter` y `ordering` a `TurnoAdmin`, pensando qué filtros usaría de verdad una secretaria un lunes a la mañana.

## Ejercicio

Sin guía: agregar un `TabularInline` de `Turno` dentro de la página de edición de `Profesional`, para ver la agenda de un profesional sin salir de su ficha.

## Challenge

Escribí una acción personalizada de admin (`actions = [...]`) que permita marcar varios turnos seleccionados como cancelados de una vez, aplicando la lógica correspondiente de `S1-05`/`S2-05` en vez de solo cambiar un campo a mano.

## Project Task

1. `admin.py` completo cubriendo los cuatro modelos principales, con `list_display`, `search_fields` y `list_filter` pensados desde el uso real del consultorio, no desde lo genérico.
2. El `TabularInline` del Ejercicio.
3. Commit: `Configurar admin de Django como interfaz de acceso del consultorio`.

## Nota sobre abstracción

Un panel de administración autogenerado a partir del modelo de datos existe en otros frameworks (Rails tiene ActiveAdmin, por ejemplo), aunque no es tan central a la filosofía del framework como en Django. El concepto —generar una interfaz de gestión de datos sin escribir vistas propias— es transferible; la implementación concreta no.
