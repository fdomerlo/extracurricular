# S2-10 — Backup, restore y consistencia de datos

## Contexto

En ingeniería de software existe una máxima inapelable: **un backup que no fue probado no es un backup; es solo una expresión de deseo**. Podés tener las mejores tablas relacionales, tests de integración pasando y un ORM optimizado, pero si un fallo de disco, un error humano o una corrupción de volumen destruye los datos y no podés restaurarlos en minutos, el sistema es un fracaso operacional.

El criterio de aprobación de S2 en el plan de estudios (`curriculum/study-plan.md` §6) exige explícitamente: *"El backup fue ejecutado, restaurado y verificado"*. En esta clase aprenderás a utilizar las herramientas canónicas de respaldo de PostgreSQL (`pg_dump`, `pg_restore`), a automatizar el proceso mediante scripts reproducibles, y a ejecutar un simulacro de recuperación ante desastres (*Disaster Recovery*) comprobando la consistencia total de la información restaurada.

---

## Concepto mínimo

**1. `pg_dump`: Copia de seguridad consistente y sin bloqueo.**  
`pg_dump` extrae una fotografía consistente de la base de datos sin bloquear las operaciones de lectura ni escritura de los usuarios (aprovechando el control de concurrencia multiversión MVCC de PostgreSQL).
- **Formato Texto Plano (`.sql`):** Genera sentencias SQL legibles (`CREATE TABLE`, `INSERT`, `COPY`). Es útil para inspección visual o migraciones entre motores, pero es lento y voluminoso para bases medianas o grandes.
- **Formato Personalizado (`-F c` — Custom Format):** Comprime los datos, genera metadatos binarios y permite a `pg_restore` restaurar en paralelo (`-j 4`) o seleccionar qué tablas restaurar selectivamente. Es el estándar de producción.

**2. `pg_restore`: Reconstrucción fiel del estado.**  
`pg_restore` interpreta el archivo binario generado por `pg_dump -F c` y reconstruye las tablas, índices, restricciones y claves foráneas en el orden estricto de dependencias:
- Parámetro `--clean`: Elimina los objetos antes de recrearlos.
- Parámetro `--if-exists`: Previene errores si las tablas no existían.
- Parámetro `-d <dbname>`: Especifica la base de datos destino.

**3. Prueba de Restauración y Verificación de Consistencia.**  
Restaurar no termina cuando el comando devuelve código 0. Debe existir una verificación automatizada que certifique:
- Que la cantidad de registros en cada tabla coincide exactamente con la base original (`COUNT(*)`).
- Que las restricciones `CHECK` y `FOREIGN KEY` siguen activas y válidas.
- Que el sistema de aplicación puede conectarse y continuar operando normalmente sin errores.

## Ejemplo trabajado conceptual

Comandos estándar de dump y restore en PostgreSQL:

```bash
# 1. Generar backup comprimido en formato Custom
pg_dump -U consultorio -d consultorio_db -F c -b -v -f /backups/consultorio_backup_20261020.dump

# 2. Restaurar sobre una base de datos limpia de recuperación
createdb -U consultorio consultorio_recuperado
pg_restore -U consultorio -d consultorio_recuperado -v /backups/consultorio_backup_20261020.dump
```

## Laboratorio

1. **Asegurar datos en la base local:**  
   Verificá que tu base `consultorio_db` tenga datos cargados (profesionales, prácticas, pacientes y turnos).
2. **Generar un dump binario:**  
   Ejecutá `pg_dump` desde tu terminal o a través de Docker:
   ```bash
   docker compose exec db pg_dump -U consultorio -d consultorio_db -F c -f /tmp/backup_test.dump
   docker compose cp db:/tmp/backup_test.dump ./backup_test.dump
   ```
3. **Simular desastre y crear base de recuperación:**  
   Creá una base nueva completamente vacía:
   ```bash
   docker compose exec db createdb -U consultorio consultorio_dr
   ```
4. **Ejecutar la restauración:**  
   Restaurá el dump sobre la base `consultorio_dr`:
   ```bash
   docker compose exec -T db pg_restore -U consultorio -d consultorio_dr -v < ./backup_test.dump
   ```
5. **Comprobar los datos restaurados:**  
   Ingresá a `psql` en la base recuperada y consultá los turnos:
   ```bash
   docker compose exec db psql -U consultorio -d consultorio_dr -c "SELECT COUNT(*) FROM turno;"
   ```

## Ejercicio

1. **Script de backup automatizado:**  
   Creá el script `scripts/backup.sh` ejecutable:
   - Debe leer las credenciales desde variables de entorno (`DB_HOST`, `DB_NAME`, `DB_USER`).
   - Debe generar un archivo nombrado con timestamp (ej. `backups/consultorio_2026-10-23_143000.dump`).
   - Debe verificar que el archivo de salida tenga tamaño mayor a 0 bytes.
2. **Script de restore y verificación:**  
   Creá el script `scripts/restore.sh`:
   - Debe recibir la ruta del archivo `.dump` como argumento.
   - Debe restaurar la base sobre una base destino indicada por variable de entorno.
   - Debe ejecutar consultas de verificación (contar filas de `paciente` y `turno`) e imprimir un reporte de éxito.

---

## Challenge

Integrá en `scripts/backup.sh` una política de rotación básica: que el script elimine automáticamente cualquier archivo de backup que tenga más de 7 días de antigüedad (utilizando el comando `find backups/ -name "*.dump" -mtime +7 -delete`).

---

## Project Task

1. Creá el directorio `scripts/` con los archivos `backup.sh` y `restore.sh`, dándoles permisos de ejecución (`chmod +x scripts/*.sh`).
2. Agregá el directorio `backups/` al archivo `.gitignore` para no subir volcados de datos pesados al repositorio de Git.
3. Creá el documento `docs/backup_verification.md` donde documentes la ejecución del simulacro de recuperación ante desastres:
   - Fecha y hora del simulacro.
   - Cantidad de registros antes y después del restore.
   - Tiempo total que demandó la recuperación.
4. Commit:
   ```bash
   git add scripts/backup.sh scripts/restore.sh .gitignore docs/backup_verification.md
   git commit -m "ops(db): automatizar scripts de backup/restore y documentar simulacro de recuperación"
   ```

## Nota sobre abstracción

La disciplina de probar periódicamente la restauración de datos es común a toda la industria tecnológica. En sistemas distribuidos en la nube, esto evoluciona hacia backups automáticos en buckets de almacenamiento de objetos (Amazon S3, Google Cloud Storage) con pruebas de restauración automatizadas en entornos aislados.
