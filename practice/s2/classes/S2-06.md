# S2-06 — El problema N+1

## Contexto

El ORM de `S2-05` hace fácil escribir código que se ve inocente y genera cientos de consultas sin que te des cuenta. Este es el bug de performance más común en cualquier proyecto con ORM, y nadie lo enseña afuera de la práctica misma — no es un tema de SQL ni de Python por separado, es específico de cómo un ORM traduce código orientado a objetos en consultas.

## Concepto mínimo

**El problema, concretamente.** Mostrar la agenda del día con el nombre del paciente de cada turno:

```python
turnos = Turno.objects.filter(fecha=hoy)
for turno in turnos:
    print(turno.paciente.nombre)  # una consulta nueva por cada turno
```

Esto ejecuta **una consulta para traer los turnos, más una consulta adicional por cada turno** para traer su paciente — N+1 consultas para N turnos. Con 5 turnos no se nota. Con 500, la página tarda segundos en cargar por algo que debería ser instantáneo.

**`select_related`** resuelve el caso de relaciones "hacia adelante" (`ForeignKey`, `OneToOne`) haciendo un `JOIN` en una sola consulta:

```python
turnos = Turno.objects.select_related("paciente", "profesional", "practica").filter(fecha=hoy)
```

**`prefetch_related`** resuelve el caso inverso (relaciones "hacia atrás" o muchos-a-muchos) con una segunda consulta usando `IN`, en vez de un `JOIN` que multiplicaría filas innecesariamente:

```python
profesionales = Profesional.objects.prefetch_related("turno_set")
```

## Demostración

El mentor escribe el loop de la agenda del día sin optimizar, y activa el log de consultas de Django:

```python
from django.db import connection, reset_queries
reset_queries()
# ... código sin optimizar ...
print(len(connection.queries))  # N+1
```

Agrega `select_related`, repite, muestra que el conteo baja a 1 o 2 consultas.

## Laboratorio

Con guía: aplicar `select_related` a otra vista o función existente del proyecto que acceda a relaciones `ForeignKey` en un loop.

## Ejercicio

Sin guía: encontrar otro punto del proyecto propenso a N+1 (por ejemplo, listar profesionales con la cantidad de turnos de cada uno) y arreglarlo con `prefetch_related` o con `annotate`/`Count` si el caso es de agregación pura.

## Nota sobre abstracción

N+1 no es un problema de Django — aparece en cualquier ORM (ActiveRecord, SQLAlchemy, Hibernate) que permite navegar relaciones como si fueran atributos de objeto. La solución conceptual (cargar relaciones por adelantado, en lote) también es universal; el nombre del método cambia entre frameworks.
