# M-S1 — Construir

## Objetivo

Demostrar que el estudiante puede construir una primera versión funcional de un dominio pequeño utilizando un workflow reproducible, testeable y versionado.

## Entregables

### Project Brief
Completo y actualizado.

### Código
Implementación funcional del dominio.

### Tests
Cobertura de las reglas críticas.

### Git
- commits coherentes;
- branch de trabajo;
- PR o revisión equivalente.

### Reproducibilidad
Otra persona debe poder:

```text
clone → install → test → run
```

sin pasos manuales no documentados.

### Bug report
Debe existir al menos un defecto documentado con reproducción, causa, corrección y test de regresión.

### Decisión técnica
Al menos un registro de decisión con alternativas y consecuencias.

## Defensa

El estudiante debe responder:

1. ¿Qué problema resuelve?
2. ¿Cómo modelaste el dominio?
3. ¿Qué reglas son invariantes?
4. ¿Cómo las probaste?
5. ¿Qué decisión cambiarías hoy?
6. ¿Qué bug fue más difícil?
7. ¿Qué uso hiciste de IA y cómo verificaste el resultado?

## Criterio

No se evalúa cantidad de código.

Se evalúa capacidad de explicar, verificar y evolucionar lo construido.
