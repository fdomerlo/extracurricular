# S4 — Diseñar sistemas

## Theme

**Scale the architecture**

## Focus

Arquitectura, concurrencia, asincronía, caching, mensajería, resiliencia y observabilidad.

## Estructura

- 16 clases principales.
- Mentoría aproximadamente cada 2 semanas.
- Trabajo autónomo entre clases.
- Proyecto longitudinal.
- Milestone al finalizar.

## Proyecto

Evolucionar el producto para soportar carga, procesos asíncronos y fallos controlados con evidencia de observabilidad.

## Regla pedagógica

La clase introduce una capacidad. El proyecto obliga a usarla en contexto. La mentoría revisa decisiones. El milestone evalúa integración.

## Clases

- **01** — Arquitectura y trade-offs
- **02** — Diseño de módulos y boundaries
- **03** — Concurrencia y paralelismo
- **04** — Programación asíncrona
- **05** — Queues y background jobs
- **06** — Caching
- **07** — Consistencia y fallos
- **08** — Mensajería y eventos
- **09** — Escalabilidad horizontal
- **10** — Rate limiting y resiliencia
- **11** — Observabilidad: logs, métricas y traces
- **12** — SLOs y capacidad
- **13** — Load testing
- **14** — Arquitectura cloud-agnostic
- **15** — Diseño de una evolución arquitectónica
- **16** — Milestone: sistema distribuido controlado

## Milestone

**M-S4 — Sistema escalable**

La calidad se evalúa por evidencia y capacidad de explicación, no por cantidad de código ni por cantidad de tecnologías utilizadas.
