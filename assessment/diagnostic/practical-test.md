# Prueba práctica diagnóstica

## Objetivo

La prueba práctica constituye la principal fuente de evidencia del diagnóstico.

Debe evaluar la capacidad de **hacer**, no solamente de reconocer.

---

## Estructura

La prueba debe contener tareas progresivas:

### Task 1 — Entorno

Verificar capacidad para:

* navegar el sistema;
* utilizar terminal;
* crear y modificar archivos;
* ejecutar un programa.

### Task 2 — Programación

Resolver un problema pequeño.

Evaluar:

* comprensión;
* descomposición;
* implementación;
* corrección.

### Task 3 — Debugging

Entregar un programa que contiene errores.

Evaluar:

* identificación;
* formulación de hipótesis;
* utilización de herramientas;
* corrección;
* verificación.

### Task 4 — Evolución

Modificar una solución existente ante un cambio de requerimiento.

Evaluar:

* comprensión del código;
* capacidad de modificación;
* impacto de cambios;
* pruebas.

### Task 5 — Explicación

El estudiante debe explicar:

* qué hizo;
* por qué;
* qué alternativas consideró;
* cómo verificó el resultado;
* qué cambiaría.

---

## Restricción

No evaluar velocidad como competencia principal.

La prioridad es:

```text
comprensión
→ razonamiento
→ ejecución
→ verificación
→ explicación
```

---

## Uso de IA

El diagnóstico debe indicar explícitamente cuándo puede utilizarse IA.

Cuando se permita:

1. registrar el uso;
2. observar cómo se utiliza;
3. exigir verificación;
4. exigir explicación del resultado.

El uso de IA no debe considerarse automáticamente positivo ni negativo.

La pregunta relevante es:

> ¿El estudiante puede evaluar y defender el resultado obtenido?

---

## Evidencia mínima

Una solución que funciona accidentalmente no constituye evidencia completa.

Para niveles superiores se requiere:

```text
solución
+
explicación
+
verificación
```
