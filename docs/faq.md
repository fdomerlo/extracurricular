# FAQ

## ¿Qué es este proyecto?

Es un curriculum open source de tres años para desarrollar capacidades profesionales de desarrollo de software mediante competencias, práctica, proyecto y evidencia.

No está diseñado como una colección de tutoriales sobre frameworks.

## ¿Reemplaza una carrera universitaria?

No.

Es una formación complementaria y práctica. No otorga un título universitario ni pretende sustituir una carrera formal.

## ¿Necesito saber programar?

Sí. El programa no comienza desde cero absoluto.

La persona que empieza debería poder leer código, escribir programas sencillos, utilizar una terminal y tener una noción básica de Git.

## ¿Qué lenguaje se utiliza?

El curriculum está centrado en competencias y no depende de un lenguaje concreto. La implementación práctica de referencia utiliza Python como lenguaje principal.

Esto permite mantener un stack coherente para aprender sin convertir el programa en una lista de tecnologías.

## ¿Tengo que usar Python?

Para seguir el material de referencia, sí es lo más conveniente.

Si trabajás sobre un proyecto propio, podés utilizar otro stack cuando exista una razón técnica o profesional. La competencia que se evalúa debe seguir siendo equivalente.

## ¿Tengo que usar Django?

No necesariamente.

El objetivo no es aprender un framework específico, sino aprender a diseñar, construir, probar, desplegar y evolucionar software. El material puede utilizar frameworks concretos como implementación de referencia.

## ¿Cuánto dura?

El recorrido está calibrado como referencia para **tres años** (seis semestres), considerando una carga estimada de ~1.495 horas totales de ingeniería y estudio.

Cada semestre se modela sobre aproximadamente 22 semanas académicas con una dedicación sugerida de **10 a 12 horas semanales**, pensada para personas que trabajan o cursan una carrera universitaria en paralelo.

## ¿Puedo completarlo en menos de tres años si le dedico más tiempo o tengo experiencia previa?

Sí, totalmente.

El programa está estructurado en torno a **competencias demostrables y evidencias observables**, no en horas de cursada fija ni en un calendario rígido. En cuanto cumplís los requisitos técnicos, testeás tu código y estás listo para defender el hito del semestre (*Evidence Milestone*), podés avanzar inmediatamente al siguiente.

La relación entre dedicación y tiempo de finalización es:

| Perfil y Dedicación Semanal | Carga por Semana | Ritmo por Semestre | Duración Total Estimada |
|---|:---:|:---:|:---:|
| **Part-time estándar** (trabaja o cursa grado en paralelo) | ~10–12 hs | ~20–22 semanas (~5 meses) | **~3 años** (36 meses) |
| **Part-time intensivo** (estudiante avanzado o dev junior) | ~18–22 hs | ~10–12 semanas (~3 meses) | **~1.5 a 2 años** (18–24 meses) |
| **Dedicación exclusiva / Full-time** (transición de carrera o intensivo) | ~35–40 hs | ~6–8 semanas (~1.5 a 2 meses) | **~10 a 14 meses** (~1 año) |

Si ya contás con experiencia previa de programación (lo cual podés mapear con la [`evaluación diagnóstica inicial`](../assessment/diagnostic/initial-evaluation.md)), los fundamentos elementales de S1 y S2 te demandarán mucho menos tiempo, permitiéndote concentrar tu esfuerzo en las áreas avanzadas de arquitectura, observabilidad y resiliencia de sistemas.

## ¿Es gratis?

Sí. El curriculum, los materiales publicados y la estructura pedagógica son open source y gratuitos.

La tutoría es un servicio separado y arancelado porque implica tiempo de acompañamiento, revisión y evaluación personalizada.

## ¿Puedo hacerlo completamente solo?

Sí.

El Reference Project existe precisamente para que una persona sin cliente o proyecto propio pueda completar el recorrido.

La modalidad autodidacta sigue el mismo curriculum y utiliza las mismas competencias y criterios de evidencia.

## ¿Entonces por qué pagar tutoría?

La diferencia no está en acceder a conocimientos ocultos.

La tutoría aporta:

- feedback sobre tu trabajo;
- code review;
- discusión de decisiones técnicas;
- ayuda para diagnosticar bloqueos;
- seguimiento del proyecto;
- evaluación de evidencia;
- preparación de milestones y defensas.

El conocimiento permanece abierto. El acompañamiento personalizado es el servicio.

## ¿El tutor escribe código por mí?

No.

El estudiante sigue siendo responsable de implementar y defender su solución. El tutor puede mostrar técnicas, ejemplos o alternativas cuando sea pedagógicamente útil, pero no debe convertirse en el desarrollador del proyecto.

## ¿Puedo usar mi propio proyecto?

Sí. De hecho, un proyecto propio puede ser más valioso porque introduce requisitos reales, usuarios, restricciones, cambios y trade-offs.

El proyecto puede ser personal, académico o profesional.

## ¿Necesito tener un cliente real?

No.

Podés usar el Reference Project o definir un proyecto propio sin cliente.

Un cliente real agrega complejidad profesional, pero no es requisito para desarrollar las competencias del curriculum.

## ¿Puedo cambiar de proyecto durante los tres años?

Sí, si existe una razón válida.

Las competencias y milestones son el elemento estable. El proyecto es el contexto donde esas competencias se ejercitan.

## ¿Cómo se evalúa?

No se evalúa principalmente por cantidad de código, features o tecnologías utilizadas.

Se evalúa mediante evidencia observable: implementación, tests, Pull Requests, documentación, code review, challenges, proyectos y defensas, según la competencia.

Ver [`../curriculum/assessment.md`](../curriculum/assessment.md).

## ¿Hay exámenes?

El modelo no se basa en exámenes tradicionales como única forma de evaluación.

Hay milestones y defensas donde el estudiante debe demostrar que comprende y puede defender lo que construyó.

## ¿Qué significa L1, L2, L3 y L4?

Son niveles de dominio:

| Nivel | Significado |
|---|---|
| L1 | Comprende y puede explicar el concepto |
| L2 | Lo aplica siguiendo una guía |
| L3 | Lo utiliza con autonomía |
| L4 | Diseña soluciones y justifica decisiones |

Las competencias y sus niveles están definidos en [`../curriculum/competencies.md`](../curriculum/competencies.md).

## ¿Puedo usar ChatGPT u otra IA?

Sí, pero la política de IA es progresiva.

El estudiante puede utilizar IA como tutor, herramienta de investigación, asistente de programación o apoyo de ingeniería según su etapa.

La regla fundamental es:

> Todo código incorporado al proyecto debe poder ser explicado, modificado y defendido por el estudiante.

## ¿Por qué enseñar IA dentro de un curriculum de desarrollo?

Porque el desarrollo profesional ya incluye herramientas asistidas por IA. El objetivo no es evitar esas herramientas, sino aprender a utilizarlas sin delegar el razonamiento ni la responsabilidad técnica.

## ¿El curriculum enseña solo backend?

No.

La progresión cubre ingeniería de software, datos, web, seguridad, arquitectura, delivery, sistemas, observabilidad, IA y competencias profesionales.

La profundidad de cada área cambia según el semestre.

## ¿Hay frontend?

Sí, como competencia práctica dentro del recorrido web. El objetivo no es formar exclusivamente especialistas frontend, sino profesionales capaces de construir y entender sistemas completos.

## ¿Por qué no enseñar muchos frameworks?

Porque los frameworks tienen ciclos de vida más cortos que las capacidades de ingeniería que se busca desarrollar.

Se utilizan tecnologías concretas cuando ayudan a aprender una competencia o a resolver una necesidad del proyecto.

## ¿Puedo contribuir al repositorio?

Sí.

Las mejoras de contenido, correcciones, bibliografía, ejemplos y material práctico son bienvenidas. Las contribuciones deberían preservar la coherencia del modelo pedagógico y explicar qué problema educativo resuelven.

## ¿Cuándo estará completo?

El curriculum completo está diseñado como roadmap de seis semestres. El material práctico se desarrolla progresivamente.

S1 es la referencia de implementación completa; los siguientes semestres pueden encontrarse en distintos estados de autoría.

Ver [`roadmap.md`](roadmap.md).

## ¿Qué necesito para empezar hoy?

1. Leer [`getting-started.md`](getting-started.md) y [`student-workflow.md`](student-workflow.md) para configurar tu repositorio.
2. Revisar el mapa curricular en [`study-plan.md`](../curriculum/study-plan.md).
3. Comenzar con las clases de [`practice/s1/`](../practice/s1/).
4. Elegir el Reference Project o definir un proyecto propio.
5. Producir evidencia observable en cada etapa.

No necesitás contar con un tutor para empezar; el currículo es 100% transitable de forma autodidacta. Si tenés dudas conceptuales o querés compartir tu proyecto con otros estudiantes, participá en **GitHub Discussions**.

## ¿Cómo solicito acompañamiento o tutoría?

La tutoría personalizada es un servicio profesional arancelado con cupos estrictamente limitados. Los protocolos y plantillas de trabajo están documentados en [`../tutoring/README.md`](../tutoring/README.md).

Para solicitar admisión o coordinar una sesión:
1. Completá la [`evaluación diagnóstica inicial`](../assessment/diagnostic/initial-evaluation.md) (o la plantilla correspondiente en [`tutoring/templates/`](../tutoring/templates/)).
2. Enviá tu solicitud por correo electrónico a **`fdomerlo@gmail.com`** con el asunto `[Extracurricular] Solicitud de Tutoría - <Tu Nombre>` adjuntando el formulario completado y el link a tu repositorio.
3. El tutor revisará tus evidencias y coordinará una breve llamada para acordar condiciones, plan de trabajo y agenda.
